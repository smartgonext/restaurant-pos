## Key Architectural Decisions

### 1. Feature-Based Routing
All hotel routes are in a single file (`hotel.ts`) grouped by feature:
```
Room Types → Rooms → Guests → Reservations → Check-In/Out → Stays → Folio
```

**Rationale:** Easy to maintain, related endpoints grouped logically

### 2. Automatic Stay Creation
Stays are created at check-in, not reservation:
```
Reservation → (pending) → Check-in → Stay (billing starts here)
```

**Rationale:** Only active guest stays accrue charges

### 3. Folio-Based Billing
All guest charges go into folio records:
- Room charges (auto-calculated)
- Service charges (room service)
- Incidental charges (minibar, laundry, etc.)
- Payments made are tracked separately

**Rationale:** Flexible, audit-able, supports partial payments

### 4. Multi-Room Reservations
Reservations can be for multiple rooms via `HotelReservationRoom` table:
```typescript
Reservation
  ├─ Room 101
  ├─ Room 102
  └─ Room 103
```

**Rationale:** Supports groups and families

### 5. Automatic Task Generation
Check-out automatically creates housekeeping task:
```
Check-out → HotelHousekeepingTask (auto-created)
```

**Rationale:** Ensures no rooms are skipped

### 6. Event Conflict Detection
Events check for time conflicts automatically:
```
New Event Start:18:00-22:00 + Existing 18:30-23:00 = CONFLICT!
```

**Rationale:** Prevents double-booking

### Add New Room Type
```bash

Content-Type: application/json

{
  "name": "Suite",
  "maxOccupancy": 4,
  "basePricePerNight": 300
```

## FAQ

**Q: How do I check room availability?**
A: Use `GET /api/restaurant/hotel/rooms/availability?checkInDate=...&checkOutDate=...`

**Q: Can a reservation have multiple rooms?**
A: Yes, use `roomSelections` array in POST /reservations

**Q: What happens when I check out a guest?**
A: Folio is calculated, housekeeping task created, room marked vacant_dirty, reservation marked checked_out

**Q: Can I add charges after check-in?**
A: Yes, use `POST /api/restaurant/hotel/stays/:id/charges`

**Q: What if two events conflict?**
A: System returns error: "Venue is already booked for the selected time"

**Q: Can I cancel a reservation?**
A: Yes, use `PATCH /reservations/:id/cancel`, but not if already checked in

## Support & Troubleshooting

### Issue: 401 Unauthorized
**Solution:** Ensure JWT token is in Authorization header:
```
Authorization: Bearer {token}
```

### Issue: Room not available
**Solution:** Check room status and existing reservations. Use availability endpoint first.

### Issue: Can't delete resource
**Solution:** May have linked records. Use cascade protection check.

### Issue: Route not found
**Solution:** Verify endpoint path. Check [Implementation Status](HOTEL_API_IMPLEMENTATION_STATUS.md) for correct path.
